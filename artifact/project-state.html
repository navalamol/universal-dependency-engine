Core Model

3-Phase Confidence Classification

Every CVE is classified before any file is touched. Hard rules — never overridden by heuristics or AI.

Phase A

Auto-apply · 95–100%

Same-major patch or minor bump. Single version in the dep tree. Written to phase-a-overrides.json and applied automatically.

SAFE upgrade · Single version
→ auto-commit on --commit flag
Phase B

Review first · 60–95%

Multiple same-major versions in the tree. A forced override is written, but the operator must review before applying.

Multi-version same-major
→ disjoint parents may allow nested override
Phase C

Manual review · <60%

MAJOR_BUMP, NO_FIX, or multi-major conflict. Moves to manual-review.md with justification. Never auto-applied — ever.

MAJOR_BUMP → Phase C always
No @^major selectors — ever

Phase 6 — UI Plan

Delivery Vehicle Decision

The goal: full configuration and report review in a visual UI — zero terminal knowledge required. The right delivery vehicle determines what users can actually do.

VS Code Extension

RECOMMENDED

Developers are already in VS Code when they need to remediate vulnerabilities. An extension adds a dedicated panel — report upload, live analysis, one-click apply — with zero installation beyond the marketplace. Full Node.js API access means it can run npm install, read workspace files, and open a terminal for advanced flows. The workspace is already the context.

PROS
  • 75M+ VS Code users, zero extra install
  • Full Node.js + filesystem access in extension host
  • Workspace context auto-detected (open project = target)
  • Webview panel for rich HTML/CSS/JS UI
  • Marketplace for discovery & auto-updates
  • Works alongside the existing CLI
CONS
  • Requires VS Code (excludes JetBrains, vim users)
  • Webview sandboxed (no direct DOM of editor)
  • Extension manifest overhead

Tauri Desktop App

A standalone GUI app using the system webview — no bundled Chromium. Tauri bundles a Rust backend that can spawn processes and touch the filesystem, with a web-tech frontend. ~10 MB install vs Electron's ~150 MB. Best for enterprise / security teams who want a dedicated tool not tied to an IDE.

PROS
  • IDE-independent, works for any team
  • ~10 MB install (vs Electron 150 MB)
  • Full filesystem + shell process access
  • Native menus, tray icon, OS integration
  • Strong candidate for Phase 2 of UI rollout
CONS
  • Requires Rust toolchain to build
  • System webview inconsistencies across OS
  • No marketplace — manual distribution
  • More complex dev setup than an extension

Electron App

Proven, largest ecosystem, ships Chromium so the UI is pixel-consistent everywhere. VS Code itself runs on Electron. More familiar for a Node.js codebase. But large install size and slower startup.

PROS
  • Node.js codebase reuse is trivial
  • Largest community + tooling (Forge, Builder)
  • Fully consistent rendering, all platforms
  • Auto-update ecosystem (electron-updater)
CONS
  • ~150 MB install, slow cold start
  • High RAM baseline (~200 MB idle)
  • No marketplace — user must download/install
  • Known security surface (Node integration)

Chrome Extension

Good for overlaying data on GitHub / GitLab PR pages — e.g. showing Phase A/B/C badges on a PR. Not a viable primary delivery: Chrome extensions cannot run shell commands, cannot read the local filesystem (except drag-and-drop), and cannot run npm install. A useful Phase 3 companion, not a foundation.

PROS
  • Overlay CVE data on GitHub / GitLab PRs
  • Zero install friction in browser
  • Good companion feature (Phase 3 add-on)
CONS
  • Cannot run shell commands or npm install
  • No real filesystem access
  • Cannot be the primary delivery vehicle
  • Manifest V3 restrictions tighten this further

Phase 6 — Build Plan

UI Implementation Roadmap

Four build stages. The VS Code extension wraps the existing CLI engine — no core logic changes. New surface, same pipeline.

Step 1 · Foundation

VS Code Extension Scaffold

Create packages/vscode-extension/ with extension manifest, activation events, and a Webview panel. Wire up the existing mendfix.js engine via Node.js child_process or direct require. Establish the message-passing contract between the webview (HTML/JS) and the extension host (Node.js).

extension.js panel.js package.json (vsce) webview bridge
Step 2 · Core UI

Report Upload & Analysis Panel

File picker for vulnerability reports (auto-detects provider from filename). Ecosystem auto-detection from workspace. Phase A/B/C breakdown view. The analysis panel shows exactly what mendfix analyze outputs — cards per library, phase badge, confidence, evidence, recommended action.

report-view.html phase-cards CVE table provider auto-detect
Step 3 · Apply Controls

One-click Apply, Commit & PR

Buttons that invoke the apply/commit/pr pipeline with progress feedback streamed into the panel. Platform selector (GitHub/GitLab/AzDO/Bitbucket) with token input stored in VS Code SecretStorage. Rollback UI if install fails. Phase C items stay read-only in the panel — no accidental auto-apply.

apply flow SecretStorage tokens progress stream rollback UI
Step 4 · Configuration

Visual Settings & Portfolio Config

A form-based settings view replacing all CLI flags — output directory, registry verify toggle, depth/simulation limits, PR defaults. Portfolio mode builder: add repos by browsing, set ecosystem per-repo, run multi-repo analysis from the panel. Export the resulting portfolio.json or run directly.

settings form portfolio builder portfolio.json export vsce publish
Step 5 · Stretch

Tauri Standalone App

For users not on VS Code — enterprise security teams, ops engineers. Build the same Webview UI as a Tauri app backed by the same Node.js engine (via sidecar). ~10 MB install, no bundled Chromium. Shares 100% of the frontend code from Step 2–3. Same features, different shell.

Tauri sidecar shared frontend OS packaging auto-update
Step 6 · Companion

Chrome Extension (PR Overlay)

A browser extension that reads open Dependabot / Renovate PRs on GitHub/GitLab and overlays Phase A/B/C badges inline. Read-only — no apply. Calls a lightweight local server (started by the VS Code extension or Tauri app) to get analysis results for the current PR's packages. Lowest priority but high visibility.

MV3 extension GitHub PR overlay local API bridge Phase A/B/C badges
